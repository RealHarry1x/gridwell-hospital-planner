The API workflow checks cover scenario/goal selection, original and adjusted
forecasts, generation, settings and hourly edits, recalculation, valid and
blocked approval, baseline comparison, energy breakdown, outage/failure/refill,
sample-assistant numbers, preset create/read/update/delete, battery carry,
revision/stale-plan rejection, idempotent approval and explicit reset.

Planner checks cover one-hour energy balances, PV accounting, battery losses,
power and capacity limits, critical protection, HVAC comfort violations,
activity budgets/windows, normal generator-off behavior, the 10% outage
threshold, fuel exhaustion and an explicit human refill. A demand adjustment
cannot remove the original critical floor.

Gemini tests cover root-only `.env` loading, exported-variable precedence,
disabled interpolation, an empty-key example, ignore rules, no-key default
startup, real SDK serialization intercepted with HTTPX MockTransport, default
and custom model IDs, single-attempt quota/authentication errors, delayed
503/504 recovery and fallback, total-timeout
cancellation, empty/unsafe replies, safe public status, allowlisted context,
privacy/read-only refusals, no credential echo/logging, and no plan/history
mutation. They use dummy credentials; they never read a real key for a paid call.

Diagnostic tests additionally verify actual SDK HTTP 400/401/403/404/429/503/504
status and symbolic error extraction, visible safe messages, suppression of
full response details, root `.env` source/model reporting, empty environment
overrides, URL-encoded keys, authorization/password/token/URL/environment-secret
redaction, no terminal-control injection, and no private thinking text. Current
SDK candidate enums, `BLOCKED_REASON_UNSPECIFIED`, primary-candidate text,
blocked/empty/thought-only/continuation/MAX_TOKENS output and missing HTTP status
are exercised. The workspace has no configured key, so these tests do not
identify the user's computer's actual account-side error; the new terminal
diagnostics make that error visible on a local retry.

Slow-reply tests intercept the installed official SDK's actual HTTP request
with HTTPX MockTransport. A 503 or 504 followed by a successful response uses
the same model, question and plan projection, awaits one 2-second delay, and
returns Gemini mode without changing the plan. Two errors fall back without
a third call. Quota/authentication errors never retry. The total deadline
cancels a pending retry delay before any later call. Safe startup policy and
retry diagnostics are checked, including credential redaction. No real-time
45-second or 100-second delay and no billable call was used in these tests.

The test dependency emits a Starlette deprecation warning about its compatible
httpx TestClient path; the tests pass. This does not affect the running app.

Friendly-chat tests verify `hi` and other greetings return a natural local
reply without making a Gemini call. General questions are sent without hospital
data, use general-chat labels and retain useful sample FAQ/arithmetic replies
without a key. An energy-plan question returns the selected backend plan's
actual simulated cost and context. Mocked Gemini calls check both scopes;
hospital commands remain refused and no test changes plan state. A local
greeting/general/energy API walkthrough also confirms the source labels. These
are API and rendering checks, not a live Gemini or interactive-browser test.

Rendering checks do not exercise browser events, layout or responsive
appearance. Use the README's walkthrough on your computer to verify those
interactions. Windows/macOS setup commands are supplied, but were not executed
on those operating systems in this environment.

The new React DOM checks exercise actual clicks and input changes: confirmed
reset and visible counts; edited-reserve recalculation and a new revision;
same-input result notice; scenario selection and explicit working settings;
new-weather draft generation without resetting history or rewriting a snapshot;
goal changes preserving hardware; editing a preset without applying it;
independent outage inputs and day-plan preservation; seven-day popup and Escape
close; failure-event default following the chosen cut; duplicate comparison-card removal; and hourly weather provenance without
the old graph range legend. jsdom does not verify real layout, scrolling,
responsive appearance or an operating system's native form behaviour.

Weather tests intercept HTTPX and verify requested variables/coordinates,
10-second timeout, radiation-to-solar conversion, one-hour cache/expiry,
defensive copies, invalid/date-out-of-range/null/bad-JSON failures, deterministic
fallback labels, scenario modifiers, unchanged critical demand and comfort
permission, real-vs-simulated endpoint metadata, and frozen weather through
reload/verify/recalculate/rehearsal. No pytest or React test calls the internet.
Live Open-Meteo availability from the user's computer is not verified here.
